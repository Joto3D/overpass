Overpass

Runs Windows programs on macOS — and keeps a Proton-style database of what actually works.

Overpass is a native macOS app that runs Windows .exe files through Wine — a Whisky/CrossOver-style launcher built for people who want an open, self-hosted option now that Whisky is discontinued. It owns its Wine engines, its bottles and its data. Nothing is proprietary and nothing phones home.

What it does

Bottles

A private Windows environment per app: its own C: drive, programs and engine, isolated from every other bottle.

Engines

Apple's Game Porting Toolkit or open-source Wine-staging, downloaded on demand — never bundled, never vendored.

Fixes

Per-game recipes applied automatically at launch, in the spirit of Proton's protonfixes.

Install App

A built-in catalog — Steam, 7-Zip, redistributables — fetched and installed into a bottle for you.

Programs

Scans a bottle's Start Menu, Desktop and Program Files and turns what it finds into a launchable grid.

Performance

Per-bottle tuning: threading, MetalFX upscaling, frame pacing, DXVK, and a Metal frame counter.

Choosing an engine

This is the one choice worth reading about before you make it, so Overpass shows the same trade-off everywhere an engine is picked.

EngineWhat it isTrade-off
Game Porting Toolkit
default		 Wine plus Apple's D3DMetal, translating DirectX 11/12 straight to Metal. Best performance for most games. Built on an older Wine, so some modern apps — including the Steam client — can fail to run. D3DMetal is under Apple's non-commercial licence.
Wine-staging The newest upstream Wine-staging, fully open source, with the widest app compatibility. DirectX goes through DXVK rather than D3DMetal, usually slower for games.

Both engines are x86_64 and need Rosetta 2. Apple plans to remove most of Rosetta starting with macOS 28, at which point these engines may stop working. Engine selection sits behind an abstraction specifically so a native arm64 build — once one exists — can be added as a single catalog entry rather than a rewrite.

The fix database

Some Windows programs need a particular nudge before they run under Wine: a font package, a registry value, a launch flag. Overpass keeps those recipes in a database and applies them for you, so you never have to know they exist. Slow steps — Winetricks verbs above all — run once per bottle and are recorded. Environment variables and launch arguments re-apply every launch, so removing a fix removes its effects with nothing left behind.

Not every finding is a fix

Some programs cannot work under Wine on macOS at all, and the most useful thing a database can do is say so before you spend twenty minutes installing one.

SeverityMeaningExample
wontRunNo bottle setting can make this work.Ubisoft Connect needs engine-level support only CrossOver has.
degradedRuns, with a limitation worth knowing first.Counter-Strike 2 plays, but VAC keeps compatibility layers off secure servers.
infoRuns fine — there's simply a better route.No Man's Sky ships a native Mac build, and its Windows build is Vulkan.

wontRun and degraded are surfaced in the app. info goes to the run log — worth recording, not worth interrupting for. You can add your own by dropping a JSON file in; a fix only has to spell out the fields it actually uses.

Honest status

Things this project knows are unfinished or unproven, stated here rather than discovered later.

AreaWhere it stands
Frame generationA Metal optical-flow estimator runs at ~1.1 ms per frame pair at 1080p and the present hook is verified against a real D3D11 game. Nothing interpolates yet — this stage produces the motion field only.
GPTK 4 enginesAn engine can be derived from a user-supplied Game Porting Toolkit 4 download. Experimental: regsvr32 d3d11.dll hangs undiagnosed and no game has rendered on one. Not yet reachable from the UI.
SigningAd-hoc signed, no Apple Developer ID. First launch needs right-click → Open; a plain double-click is blocked by Gatekeeper.
D3DMetal scopeMeasured: GPTK translates 64-bit D3D11/D3D12 only. D3D9 is wined3d on both architectures, as is the 32-bit D3D11, so D3D9 and 32-bit titles never reach Metal however well they render.

Building from source

No Xcode project — Swift Package Manager plus a bundling script.

git clone https://github.com/Joto3D/overpass.git
cd overpass
swift build -c release
./scripts/bundle.sh

There is a headless smoke test that creates a bottle, launches Notepad in it and tears everything down again, plus a unit suite:

.build/debug/Overpass --self-test   # unit suite
.build/debug/Overpass --check       # real bottle, real Wine

Licensing, in two halves

Overpass's own source is GPL-3.0-or-later. That covers the app, not the engines it downloads at runtime and never redistributes: Wine is LGPL-2.1+, and Apple's D3DMetal comes under Apple's non-commercial licence, which you accept when you install that engine. Keeping engines out of the repository is what keeps the boundary clean.

The per-game fix data — every executable name, Winetricks verb, registry entry, note and source — is dedicated to the public domain under CC0 1.0, separately from the code. A fix recipe is a statement of fact, and facts belong to everybody. The dedication exists so recipes can move freely between Overpass and projects whose licences are otherwise incompatible with each other.

The flip side, stated plainly. Because the data is CC0 rather than GPL, entries may not be copied out of a GPL fix database — umu-protonfixes, Bridgeplay, proton-ge — or a proprietary one. Read the underlying fact from a public source and write the entry yourself, citing it.

Every built-in fix was produced that way. source is mandatory, and the self-test fails the build on a fix that cites nothing.
